Exporting and sharing a game

EXPORT builds a single self-contained HTML file: your source is substituted into src/standalone_inlined.txt, the template committed in this repository. It needs one thing from you — the editor has to be served over HTTP, because a page opened as file:// cannot fetch the template, and the export then fails with “still downloading html template” forever. Run npm start and use localhost:8020, or use this site. The setup page proves it in three checks.

Exported games link back to this site unless the game sets its own homepage in the prelude. SHARE (a gist link) works from any host in this fork: it asks for a GitHub personal access token through auth_pat.html rather than an OAuth callback. npm run check:export verifies the template before you rely on it.

The command line

All of these are run from the repository root. Node 18+ for the npm and psmap lines, uv for the palette tools; neither needs npm install. Where each command has to be run from, in detail.

CommandWhat it does
npm startServe this checkout at localhost:8020 (or runserver.sh / runserver.bat)
npm testThe map editor's suite: parser, spreadsheet and REXPaint bridges, round trip
npm run check:gamesEvery demo game still opens in the map editor
npm run check:palettesThe palette set, its generated files and the vendored map editor copy
npm run check:exportThe standalone export template is present and complete
npm run buildMinified bin/ site and a rebuilt export template (needs npm install)
psmap export <game>Level grids out to .xlsx, .csv, .tsv or REXPaint .xp
psmap import <game> <edited>Edited grids spliced back in, leaving every other line alone
psmap info <game>Summarise levels, glyphs and legend
psmap check <game>…Can the editor read this game? Exit 1 if not — the CI-friendly one
uv run tools/palette_analysis.pyRate the shipped palettes; --write regenerates everything derived from palettes/
uv run tools/palette_curate.pyRate and adopt candidate palettes you have not shipped yet
uv run tools/palette_test.pyThe palette checks on their own
uv run tools/sync_map_editor.pyKeep the standalone map editor repository in step with the copy here

psmap is node puzzlescript-map-editor/src/cli.js; run npm link inside puzzlescript-map-editor/ to get the short name. The engine's own tests live at src/tests/tests.html and run in a browser.

Upstream, and who made this

PuzzleScript Next is David Smith's project, and this is a fork of it. For the engine as its author ships it, and for support, go there rather than here: the stable release, the dev version and david-pfx/PuzzleScriptNext, with the PuzzleScript forum for questions. The engine in turn combines PuzzleScript by increpare, PuzzleScript Plus by Auroriax, Pattern:Script by Clement Sparrow and PuzzleFAB.

This fork adds the palette set, the map and sprite editor, this front page and the setup page: fortress-rhythm/PuzzleScriptNext, published from the repository root by .github/workflows/pages.yml. Example games in the gallery and in src/demo/ keep their own authors' links and credits.
