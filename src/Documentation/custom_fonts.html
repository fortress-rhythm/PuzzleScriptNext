Adding a Custom Font

By default, title screens, menus, messages and the status line are drawn in a plain Monospace system font. The custom_font prelude directive lets any individual game swap that for a real font file instead — a pixel font you drew yourself, one you bought or downloaded, whatever fits the game. This page is a step-by-step walkthrough of doing that, using a free pixel font (Abaddon Bold by Nathan Scott) as the worked example.

This is a per-game setting, not an engine setting. It would be technically possible to bake one specific font into the engine itself as the new default for every game (replacing the Monospace fallback in src/js/graphics.js), but that's deliberately not what this page shows you how to do: it would silently reskin every game built with this engine that doesn't ask for it, which is more confusing than useful. Use custom_font in the games that actually want a particular look; leave the ones that don't alone.

1. Get a font file

You need the actual font file (.ttf, .otf or .woff2) — not a link to a page about the font. A few common sources:

  • A pixel-font editor like BitFontMaker2 lets you draw your own glyph-by-glyph and export it as a downloadable .ttf.
  • Marketplaces like itch.io have many free and paid pixel fonts, usually packaged as a .zip of one or more .ttf/.otf files.
  • Google Fonts works too, and can be linked to directly by URL instead of embedded (see step 4).

Check the license — including the font file's own metadata, not just the page you got it from. A font you drew yourself is obviously fine. A downloaded one usually says what's allowed, but different sources for the same font can disagree: the Abaddon Bold example used on this page comes as a .zip whose readme.txt says "CC BY 3.0", but the font file itself has "CC BY-ND 3.0" (No Derivatives) baked into its own name table. Either way, embedding the exact, unmodified file (as this page does) is fine; it's only if you modify the font first — subsetting it, re-hinting it, editing glyphs — that the stricter reading matters. A font page with no license mentioned at all is not automatically free to redistribute inside your game — check before shipping.

2. Check the file size

You're about to embed this file's entire contents directly into your game's source. Pixel fonts are normally small (single-digit to low-double-digit KB), which is exactly what makes this practical. Abaddon Bold, for example, is about 15KB. If a font file is hundreds of KB or more, either look for a lighter one or host it externally instead (step 4b).

3. Base64-encode it

The engine loads a custom font as a data: URI: the font's raw bytes, encoded as base64 text, inlined directly into a prelude line. This is what makes it permanent — the font travels inside the .txt game file itself, so it keeps working even if the site you originally got it from disappears, and works identically when the game is shared, exported to standalone HTML, or embedded elsewhere.

If you use Python (with uv or otherwise), base64 is in the standard library, so no install is needed:

uv run python -c "import base64; print(base64.b64encode(open('AbaddonBold.ttf','rb').read()).decode())" > font.b64.txt

Or without uv:

python3 -c "import base64; print(base64.b64encode(open('AbaddonBold.ttf','rb').read()).decode())" > font.b64.txt

If you'd rather not touch a terminal, a web tool like File to Base64 works too — pick the "Data URI" output format.

4. Add it to your prelude

Paste the result as a single prelude line (it'll be one very long line — that's expected):

custom_font data:font/ttf;base64,AAEAAAAKAIAAAwAgT1MvMltTiOMAAAEoAAAAYGNtYXCIGsDS...

Optionally tune the size with font_size (an em multiplier, 1 = default):

font_size 1.5

4b. Alternative: link to a font URL instead of embedding it

custom_font also accepts a plain URL to a .woff2/.ttf file, which skips the base64 step entirely:

custom_font https://fonts.gstatic.com/s/vt323/v17/pxiKyp0ihIEF2isfFJU.woff2

This is quicker to set up, but it's not permanent in the same sense as embedding: if that URL ever goes away or changes, the game silently falls back to Monospace. It's a reasonable choice for something like a Google Fonts link (which Google effectively guarantees to keep serving), but not for a one-off download link from a font marketplace or gallery page — embed those instead.

5. Test it

Custom fonts only affect the title screen, menus, message screens and the status line — they don't change how objects are drawn on the grid (for that, see sprite_size and the objects' own pixel art). Load your game and check:

  • The title screen and main menu.
  • Any message screens your game uses.
  • Every character your text actually uses, especially accented letters or symbols — a font exported from a pixel-font editor or with a narrow glyph set can be missing some of them, and a missing glyph will usually just render blank.

There's a working, ready-to-open example in the demo folder: try the Custom Font Demo in the editor (or view its source at demo/next/custom_font_demo.txt). It embeds Abaddon Bold exactly as described above.
